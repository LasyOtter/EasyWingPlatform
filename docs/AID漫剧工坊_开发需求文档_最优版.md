## 0. 快速理解

### 0.1 一句话定位

> 输入一段剧本或小说，系统拆角色 / 场景 / 道具、出设定图、生成分镜脚本与分镜图、把分镜转成视频、配上角色音色与口型，最后拼成可导出的成片；同时提供模型接入、计费、任务调度、用户体系、在线升级等一整套平台能力。

### 0.2 核心价值

**市面现状**：多数开源 AI 内容项目只做**单点能力**（只出图、或只出视频）  
**本项目价值**：把「剧本 → 资产 → 分镜 → 图片 → 视频 → 配音 → 成片」整条生产链条收敛进同一个工程

### 0.3 我能用它做什么？

| 创作方向 | 可产出内容 | 典型用户 |
| --- | --- | --- |
| AI 漫剧 / 短剧 | 分集剧本、角色与场景资产、分镜图、视频片段、角色配音、成片预览 | 个人创作者、自媒体 |
| AI 影片 / 短片 | 镜头规划、参考素材整理、视频生成、音画合成 | 小型工作室、广告团队 |
| AI 条漫 / 静态漫画 | 故事与角色设定、连续分镜图、静态漫画资产管理 | 漫画创作者、IP 孵化团队 |

### 0.4 核心工作流（七步）

```
剧本创作 → 素材准备 → 分镜设计 → 图片生成 → 视频生成 → 音画同步 → 视频预览
   ↓          ↓          ↓          ↓          ↓          ↓          ↓
  文本      资产库     分镜脚本    分镜图     视频片段     配音+口型    成片导出
```

**关键设计**：  
- 每步可**独立执行**，也可作为**线性向导**推进  
- 前置步骤未完成时，后续步骤给出**明确阻塞提示**而非静默失败  
- 支持在已解锁的步骤间**任意跳转与回改**
- **中间产物可独立交付**：大纲、视觉设定、编号资产、分镜脚本均可版本化并复用

### 0.5 技术栈速览

## 2. 项目概述

### 2.1 背景与定位

原文事实：市面多数开源 AI 内容项目只做**单点能力**（只出图、或只出视频）。本项目把「剧本 → 资产 → 分镜 → 图片 → 视频 → 配音 → 成片」整条生产链条收敛进同一个工程，用**可视化工作流驱动 AI 模型批量生成内容**，并附带"能对外运营"的平台能力（模型接入、计费、任务调度、用户体系、在线升级）。

### 2.2 产品目标

| 编号 | 目标 | 说明 | 对应亮点 |
| --- | --- | --- | --- |
| G1 | 端到端贯通 | 单项目内完成从文本到成片的全部环节，无需跨工具搬运，支持批量与续生 | H1 |
| G2 | 模型无关 | 文本 / 图片 / 视频 / 语音四类模型通过统一 Provider 协议接入，可替换、可扩展 | H2 |
| G3 | 视觉一致 | 解决 AI 漫剧最大痛点"同一角色每张图都不一样" | H5 |
| G4 | 成本可信 | 报价与正式提交共用同一套解析/命中/预冻结逻辑，避免"先跑后扣"的黑盒 | H3 |
| G5 | 任务可靠 | 批量任务在服务重启、停止、续生后仍保持互斥与可恢复 | H4 |
| G6 | 可直接商业化 | 多用户、充值、订单、支付、返佣、实名、内容审核齐备，非 demo 级 | H6 |
| G7 | 低门槛交付与运维 | 一条命令部署、在线升级可回滚、后台入口随机化 | H7-H9 |
| G8 | 中间产物可交付 | 大纲、视觉设定、编号资产、分镜脚本、尾帧衔接均可独立确认、版本化并复用 | H11 |
| G9 | 平台通用性 | 风格、节奏、模板作为可配置项，不将特定创作方法固化为平台约束 | H12 |

### 2.3 目标用户

原文事实：

- **个人创作者与小型工作室**：需要一套可控、可私有化、按自己模型计费的创作台。
- **希望把 AI 内容生产做成 SaaS 的团队**：需要多用户、充值、订单、后台运营、在线升级。

## 3. 核心概念

### 3.1 术语表（单一事实来源）

> 本章节是全文术语的**唯一权威定义**。所有模块文档、接口文档、数据库设计中涉及术语的内容，均以本章节为准。

| 术语 | 英文 | 含义 | 所属领域 |
| --- | --- | --- | --- |
| 项目（Project） | Project | 作品级容器，承载剧本类型、画面比例、画风快照等全局配置 | 内容管理 |
| 分集（Episode） | Episode | 剧集结构下的单集单元；电影/短片结构下等价于整片 | 内容管理 |
| 资产（Asset） | Asset | 角色、道具、场景等可复用实体资源，含参考图、音色绑定 | 资产管理 |
| 分镜（Shot / RPS） | Shot / RPS | 单个镜头，含画面描述、台词、生成提示词、图片与视频产物 | 分镜工作台 |
| 镜头组 | Shot Group | 由宫格/多镜头拆分形成的镜头集合 | 分镜工作台 |
| 画风快照 | Style Snapshot | 项目级画风参数快照，用于约束全项目画风一致 | 视觉一致性 |
| 视觉设定快照 | Visual Config Snapshot | 包含风格描述、色盘、画幅、负面约束及模型模板的完整配置快照 | 视觉一致性 |
| SKU | SKU | 计费单元，由模型 + 参数组合命中 | 计费体系 |
| 预冻结 / 结算 | Pre-freeze / Settlement | 生成前冻结余额额度，任务结束后按实际消耗结算 | 计费体系 |
| Provider | Provider | 外部模型供应方的适配实现，分文本/图片/视频/语音四类 | 模型编排 |
| 逻辑槽（Slot） | Logical Slot | 批量任务的并发占位，用于判活与防重 | 任务系统 |
| 续生 | Continuation | 对已生成内容继续生成/补齐的增量操作 | 任务系统 |
| 资产编号 | Asset ID | 项目内资产的稳定唯一标识，可配置编号规则（如 C/S/P 前缀体系） | 资产管理 |
| 风格块 | Style Block | 可复用的风格描述文本，包含正面特征与约束条件 | 视觉一致性 |
| 色盘 | Color Palette | 项目级色彩契约，定义基准主色与扩展色 | 视觉一致性 |
| 硬约束层 | Hard Constraint | 强命令式约束（负向词清单、禁用项），提升模型遵从度 | 视觉一致性 |
| 尾帧接力 | Frame Handoff | 上一集/镜末帧作为下一集/镜首帧参考的连续性机制 | 分镜工作台 |
| 提示词模板 | Prompt Template | 按 Provider 能力将结构化字段编译为最终提示词的模板 | 模型编排 |
| 阶段门 | Stage Gate | 上游产物变更时的下游失效检测与提示机制 | 质量管理 |

### 3.2 资产编号规范（可配置）

> **设计原则**：资产需有项目内稳定唯一的编号。系统提供默认 C/S/P 编号体系，但允许用户自定义规则。

**默认编号体系（推荐）**：

| 类别 | 前缀 | 范围 | 示例 | 描述 |
|----------|--------|---------|-------------|-------------|
| 角色 | C | C01-C99 | C01 夸父·标准资产版 | 每个主要角色至少两版（标准像+情节海报） |
| 场景 | S | S01-S99 | S01 大荒原·烈日正打 | 关键位置三机位（正打/反打/侧面） |
| 道具 | P | P01-P99 | P01 夸父手杖 | 重要物品白底展示 |

**自定义编号支持**：
- 允许用户配置自己的编号前缀与规则
- 编号分配逻辑可插拔（自增、手动指定、UUID）
- 提示词中的 `@资产[名称]` 语法自动解析为实际编号

### 3.3 创作模式枚举（配置化设计）

| 模式 | 适用场景 | 能力集 | 可配置项 |
| --- | --- | --- | --- |
| 电影 / 短片 | 单集短片、宣传短片、漫画视频 | 单分集、全功能 | 时长、画幅 |
| 电视剧集 | 连载漫剧、连续剧 | 多分集、全功能 | 单集时长、总集数 |
| 剧情演绎 | 角色对话、剧情推进、镜头表演 | 重对话、轻旁白 | 对白/旁白比例 |
| 真人解说漫 | 旁白为主、真人解说漫、知识或故事讲解 | 重旁白、轻对话 | 旁白风格 |
| 图生视频 | 已有稳定人物图，希望用图片约束视频 | 单参考图模式 | 参考图权重 |
| 多参生视频 | 需要同时引用场景、角色、道具等多张素材 | 多参考图模式 | 参考图优先级 |
| 专业版 | 需要复杂镜头组织和更精细控制 | 完整功能集 | 全部可配 |
| 自动网格模式 | 希望自动生成宫格镜头并形成镜头组 | 自动拆分宫格 | 宫格密度 |

> **需求**：创作模式须作为**配置项而非代码分支**，每种模式需声明其能力集（是否支持多参、是否自动拆宫格、是否走特定提示词模板等）。模式配置应支持导出/导入，便于用户分享与复用。

### 3.4 节奏模板（可选，建议）

系统可提供预设节奏模板，但不强制使用。用户可根据自己的需求自定义。

**示例：短剧15秒模板**（借鉴实践经验）：

| 项 | 约定 | 系统支持 |
| --- | --- | --- |
| 单集时长 | 15 秒 | 分镜脚本按 13~15s/集规划镜头数（3~7 个） |
| 集数换算 | N = round(总时长 / 15s) | "时长 X 分钟"自动折算集数并提示 |
| 开场策略 | 前 3 秒需有强画面/强台词/强冲突/强反差/强悬念 | AI 编剧提示词模板强制要求，产出后校验 |
| 集间钩子 | 每集结尾留钩子 | 校验规则：末镜不得为纯交代性收尾 |
| 反转分布 | 第二幕末颠覆性大反转，第三幕揭示真相 | 大纲评审项 |

> **注意**：此模板基于特定实践经验，不应作为平台唯一标准。用户可创建自己的节奏模板（如 30 秒/集、60 秒/集等）。

## 4. 使用场景与创作模式

### 4.1 主线流程（七步，原文）

| 步骤 | 名称 | 关键动作 | 阻塞条件 | 产物 |
| --- | --- | --- | --- | --- |
| 1 | 项目配置 | 确定画面比例、剧本类型、模型策略、创作模式、画面风格 | 无 | 项目配置快照 |
| 2 | 剧本创作 | 编写、粘贴或导入本集剧本 | 项目未创建 | 剧本文本 + 版本 |
| 3 | 素材准备 | 从剧本提取资产，并生成或导入参考图 | 剧本未保存 | 资产库（编号体系） |
| 4 | 分镜设计 | 把故事拆成镜头，编写画面、台词、生成提示词，并生成分镜图 | 资产未就绪 | 分镜脚本 + 分镜图 |
| 5 | 视频生成 | 基于分镜图和参考资产生成视频片段 | 分镜图未生成 | 视频片段列表 |
| 6 | 音画同步 | 生成角色配音，并把配音与分镜视频做口型同步 | 视频未生成 | 配音文件 + Lip Sync |
| 7 | 视频预览 | 视频、配音、字幕、音乐放入时间轴，预览并导出成片 | 音画未同步 | 成片文件 |

> **需求**：七步须可作为**线性向导**推进，也允许在已解锁的步骤间**任意跳转与回改**；前置步骤未完成时，后续步骤应给出明确的阻塞提示而非静默失败。

### 4.2 中间产物可交付（工程化增强）

| 环节 | 可交付产物 | 版本化 | 复用场景 |
| --- | --- | --- | --- |
| 剧本规划 | 故事梗概、人物设定、分集大纲 | ✅ | 团队评审、AI 续写输入 |
| 视觉设定 | 风格描述、色盘、画幅、负面约束、模板 | ✅ | 跨项目复用、风格库 |
| 资产准备 | 编号资产清单、参考图、提示词 | ✅ | 跨集复用、素材管理 |
| 分镜设计 | 分镜脚本、时间轴、提示词 | ✅ | 修改重生成、文档交付 |
| 连续性管理 | 尾帧描述/图、衔接说明 | ✅ | 集间连续性 |
| 生成任务 | 产物、成本、任务关联 | ✅ | 修补、对账、复现 |

> **阶段门机制**：上游产物变更时，系统提示下游可能过期的产物，由用户决定是重新生成、保留旧产物还是忽略。所有选择进入版本历史。

### 4.3 端到端示例

**示例场景**：5 集×15 秒的《鲁智深醉闹五台山》短剧制作

**输入**：一段 500 字的水浒传选段

**产出清单**：
1. ✅ 完整剧本（5 集剧本，每集 3-5 个镜头，含台词与画面描述）
2. ✅ 视觉设定（风格描述、色盘声明、画幅配置）
3. ✅ 资产清单（C01 鲁智深、C02 众僧、S01 五台山大殿、S02 山门、P01 禅杖、P02 酒葫芦）
4. ✅ 分镜图（每集 3-5 张分镜图，统一画风）
5. ✅ 视频片段（5 段×15 秒视频）
6. ✅ 配音文件（鲁智深音色 + 旁白音色）
7. ✅ 成片预览（75 秒完整视频，含字幕与背景音乐）

**关键质量指标**：
- 角色一致性：同一角色在 ≥10 张分镜图中，人工评审判定形象一致的比例 ≥ 80%
- 视觉一致性：所有分镜图使用声明的色盘，无跑色
- 任务可靠性：批量生成过程中重启后端，任务不重复、不悬挂，可继续完成
- 成本可预测：报价与实际结算金额误差 ≤ 5%

## 5. 功能需求

> **优先级**：P0 = MVP 必须；P1 = 商业化上线必须；P2 = 增强。
> **状态标注**：**原文** = 来源文章明确描述；**推断** = 为保证可实现性补充的定义；**建议** = 借鉴实践经验的可选增强。

### 5.1 模块一：项目 / 剧本 / 分集管理（P0）

| 编号 | 需求 | 说明 | 验收口径 |
| --- | --- | --- | --- |
| FR-1.1 | 作品级项目 | 创建项目，配置画面比例、剧本类型、模型策略、创作模式、画面风格 | 新建项目 → 保存配置 → 配置可回显与修改 |
| FR-1.2 | 双结构支持 | 支持「电影（单片）」与「剧集（多分集）」两种内容结构 | 切换结构类型 → UI 调整 → 数据结构正确映射 |
| FR-1.3 | 剧本输入 | 支持在线编写、粘贴、文件导入三种方式 | 三种方式导入同一剧本 → 解析结果一致 |
| FR-1.4 | 剧本版本 | 剧本需维护版本历史，可回溯与对比 | 修改剧本 5 次 → 版本列表显示 5 个版本 → 可还原到任意版本 |

| NFR-10 | 国际化/编码 | 中文界面与中文提示为默认；编码 UTF-8 | 检查界面 → 中文显示正常 |
| NFR-11 | 移动端 | 用户端含 `/mobile` 路由与移动端 UA 拦截（`proxy.ts`），需保证移动端可访问基础链路 | 手机访问 → 自动跳转 mobile → 功能正常 |
| NFR-12 | 配置可序列化 | 视觉设定快照、节奏模板、提示词模板须可完整导出/导入（JSON Schema 固定），可作为跨项目模板分发 | 导出快照 → 新项目导入 → 配置生效 |
| NFR-13 | 提示词可审计 | 每次生成提交的最终提示词（含注入的风格/色盘/约束）须落库留存，支持回放与问题定位 | 生成任务 → 查看提示词 → 可追溯到字段来源 |
| NFR-14 | 模板生态 | 内置模板库应提供可复用的"风格包"（风格描述+色盘+约束+资产模板），新增模板不改代码 | 上传新风格包 → 用户可选择 → 应用生效 |

## 9. 部署与交付要求

### 9.1 方案 A：生产级一键部署（推荐，Docker）

前置条件：全新 64 位 Linux 服务器；关闭 RocketMQ 且中间件同机时最低 **2 核 / 4GB / 40GB 磁盘**。

```bash
cd /root && if command -v curl >/dev/null 2>&1; then \
  curl -fL --retry 3 --connect-timeout 15 -o /root/aid-install.sh https://gitee.com/gzxx-2025/aid-studio/raw/master/deploy/aid.sh || \
  curl -fL --retry 3 --connect-timeout 15 -o /root/aid-install.sh https://raw.githubusercontent.com/gzxx-2025/aid-studio/master/deploy/aid.sh; \
elif command -v wget >/dev/null 2>&1; then \
  wget -O /root/aid-install.sh https://gitee.com/gzxx-2025/aid-studio/raw/master/deploy/aid.sh || \
  wget -O /root/aid-install.sh https://raw.githubusercontent.com/gzxx-2025/aid-studio/master/deploy/aid.sh; \
else echo 'Please install curl or wget first'; exit 1; fi && \
sudo env AID_REMOTE_BOOTSTRAP=1 AID_RELEASE_CHANNEL=auto bash /root/aid-install.sh install
```

安装后常用命令：

```bash
sudo aid default    # 查看用户端 / 管理端访问地址、初始账号
sudo aid            # 交互式管理菜单
sudo aid status     # 服务与中间件状态
sudo aid logs       # 日志
```

默认入口：

| 入口 | 默认地址 | 说明 |
| --- | --- | --- |
| 用户端 | `http://SERVER_IP/` | 默认 80，可用 `HTTP_PORT` 调整 |
| 管理端 | `http://SERVER_IP:8089/<12位随机访问码>` | 访问码首次部署自动生成 |
| 后端 API | `http://SERVER_IP:8080/` | 通常经 Nginx 反代 |

初始管理员：`admin / admin123` —— **首次登录后必须立即改密码**。

## 10. 验收标准

### 10.2 性能验收

| 编号 | 指标 | 目标值 | 验收方法 |
| --- | --- | --- | --- |

| 编号 | 亮点 | 需求含义 | 差异化价值 |
| --- | --- | --- | --- |
| H1 | 真正打通"剧本到成片" | 分集、资产、分镜、视频、配音、导出串成可复用流水线，支持批量与续生 | 市面多数开源项目只做单点能力 |
| H2 | 模型无关的可配置 Provider 层 | 四类统一协议 + 可配置异步协议/回调/轮询 + 同源产物持久化 | 避免供应商锁定 |
| H3 | 能力与计费强一致 | 报价与提交共用解析/SKU/预冻结逻辑，前端入口可见确定或预估费用 | 用户成本透明可控 |
| H4 | 工程级任务治理 | 项目+剧集+逻辑任务类型原子防重，批量逻辑槽判活，重启/停止/续生后仍互斥可恢复 | "同类项目最容易崩的地方" |
| H5 | 资产一致性设计 | 角色形态、场景、道具、画风快照、参考图别名去重、能力截断 | 解决 AI 漫剧最大痛点 |
| H6 | 开箱即用商业化 | 多用户、充值、订单、支付、返佣、实名、内容审核 | 非 demo 级，可直接运营 |
| H7 | 自托管 + 一条命令部署 | `aid.sh` 全流程自动化，首次部署强制人工确认配置 | 降低部署门槛 |
| H8 | 在线升级可回滚 | 三端同版本构建、增量 SQL、备份、健康检查、失败自动恢复、资源感知并发 | 生产环境可用 |
| H9 | 管理后台入口随机化 | 12 位随机访问码，避免后台路径被扫描 | 安全加固 |
| H10 | 前后端可独立开发 | 多模块单体 + 双前端，架构清晰，二次开发门槛低 | 提升开发效率 |
| H11 | 中间产物可交付 | 大纲、视觉设定、编号资产、分镜脚本、尾帧衔接均可独立确认、版本化并复用 | 工作流更专业，协作更清晰 |
| H12 | 平台通用性与模板化 | 风格、节奏、提示词作为可配置模板，不将特定创作方法固化为平台约束 | 适应更多创作风格与流派 |
| H13 | 质量管理体系 | 可配置的质量检查门、阶段门失效提示、实测复盘闭环 | 保证质量不回归 |
| H14 | 提示词可审计 | 最终提示词落库留存，可追溯到字段来源，支持回放与问题定位 | 问题可复现、可修复 |

## 12. 风险与约束

| 编号 | 风险 / 约束 | 应对 | 优先级 |
| --- | --- | --- | --- |
| R1 | **开源代码不含官方素材包** | 初始化 SQL 引用的官方图片、音色样本、示例视频单独分发（`aid-official-assets_<VERSION>.tar.gz`），需从官网或 Release 公告获取后导入存储，否则部分示例页图片 404 | P0 |
| R2 | **AI 生成要花钱** | 模型调用、服务器、存储均产生费用；生成质量取决于所选模型与输入素材。需在 UI 侧明确成本提示与预算控制 | P0 |
| R3 | **生产环境别用 Beta 渠道** | 上线前将数据库、`uploadPath`、配置文件做异机备份；升级会重建三端并有短暂资源峰值 | P1 |
| R4 | **后台访问码不要丢** | 忘记可在 `aid_config` 表按 `category='admin_entry'`、`config_name='access_code'` 查询，或登录后重新生成 | P1 |
| R5 | **低配机器先降级** | RocketMQ 开启时建议 6 核 / 12GB 以上；仅本地验证可 4 核 / 4GB，但需调低 JVM 与 MQ 内存 | P1 |
| R6 | 默认口令风险 | `admin/admin123` 为公开默认值，必须在首次登录强制改密（FR-15 与 NFR-4） | P0 |
| R7 | 上游模型合规 | 内容审核与实名须前置到生成链路，避免违规内容产出 | P1 |
| R8 | 第三方许可证 | 管理端部分基础框架基于 RuoYi-Vue（MIT），须保留 LICENSE 与致谢 | P0 |
| R9 | **风格配方跨端套用**〔实践经验〕 | 图片端风格块直接复用到视频端可能效果不佳；建议双端分离维护，并在数据模型层区分字段 | P2 |
| R10 | **长提示词风格稀释**〔实践经验〕 | 首行风格行单独存在会被长正文稀释；可在每时间段落嵌入风格词 + 参考行加画风锁定语 | P2 |
| R11 | **上游队列假失败**〔实践经验〕 | "队列满"常以 HTTP 200 + code 字段返回，若判为失败会导致任务重建、撞队列上限；须按可重试处理 | P1 |
| R12 | **脚本中断≠任务失效**〔实践经验〕 | 本地轮询 abort 后服务端任务仍有效，续跑必须复用 task_id，否则浪费队列位 | P1 |
| R13 | **配乐成本与合规** | 多数视频模型不生成音乐，配乐须后期混入且注意版权；用合成音床兜底时须在成片标注 | P1 |
| R14 | **模板不是约束** | 风格模板、节奏模板是可选参考，不应强制所有用户使用；平台应保持通用性与灵活性 | P0 |
