## 1. 项目概述

### 1.1 背景与定位

原文事实：市面多数开源 AI 内容项目只做**单点能力**（只出图、或只出视频）。本项目把
「剧本 → 资产 → 分镜 → 图片 → 视频 → 配音 → 成片」整条生产链条收敛进同一个工程，用**可视化工作流驱动 AI 模型批量生成内容**，并附带"能对外运营"的平台能力（模型接入、计费、任务调度、用户体系、在线升级）。

一句话概括（原文）：

> 输入一段剧本或小说，系统拆角色 / 场景 / 道具、出设定图、生成分镜脚本与分镜图、把分镜转成视频、配上角色音色与口型，最后拼成可导出的成片；同时提供模型接入、计费、任务调度、用户体系、在线升级等一整套平台能力。

### 1.2 产品目标

| 编号 | 目标 | 说明 |
| --- | --- | --- |
| G1 | 端到端贯通 | 单项目内完成从文本到成片的全部环节，无需跨工具搬运，支持批量与续生 |
| G2 | 模型无关 | 文本 / 图片 / 视频 / 语音四类模型通过统一 Provider 协议接入，可替换、可扩展 |
| G3 | 视觉一致 | 解决 AI 漫剧最大痛点"同一角色每张图都不一样" |
| G4 | 成本可信 | 报价与正式提交共用同一套解析/命中/预冻结逻辑，避免"先跑后扣"的黑盒 |
| G5 | 任务可靠 | 批量任务在服务重启、停止、续生后仍保持互斥与可恢复 |
| G6 | 可直接商业化 | 多用户、充值、订单、支付、返佣、实名、内容审核齐备，非 demo 级 |
| G7 | 低门槛交付与运维 | 一条命令部署、在线升级可回滚、后台入口随机化 |

### 1.3 目标用户

原文事实：

- **个人创作者与小型工作室**：需要一套可控、可私有化、按自己模型计费的创作台。
- **希望把 AI 内容生产做成 SaaS 的团队**：需要多用户、充值、订单、后台运营、在线升级。

### 1.4 产出物范围（创作方向）

| 创作方向 | 可产出内容 |
| --- | --- |
| AI 漫剧 / 短剧 | 分集剧本、角色与场景资产、分镜图、视频片段、角色配音、成片预览 |
| AI 影片 / 短片 | 镜头规划、参考素材整理、视频生成、音画合成 |
| AI 条漫 / 静态漫画 | 故事与角色设定、连续分镜图、静态漫画资产管理 |

### 1.5 术语表

| 术语 | 含义 |
| --- | --- |
| 项目（Project） | 作品级容器，承载剧本类型、画面比例、画风快照等全局配置 |
| 分集（Episode） | 剧集结构下的单集单元；电影/短片结构下等价于整片 |
| 资产（Asset） | 角色、道具、场景等可复用实体资源，含参考图、音色绑定 |
| 分镜（Shot / RPS） | 单个镜头，含画面描述、台词、生成提示词、图片与视频产物 |
| 镜头组 | 由宫格/多镜头拆分形成的镜头集合 |
| 画风快照 | 项目级画风参数快照，用于约束全项目画风一致 |
| SKU | 计费单元，由模型 + 参数组合命中 |
| 预冻结 / 结算 | 生成前冻结余额额度，任务结束后按实际消耗结算 |
| Provider | 外部模型供应方的适配实现，分文本/图片/视频/语音四类 |
| 逻辑槽（Slot） | 批量任务的并发占位，用于判活与防重 |
| 续生 | 对已生成内容继续生成/补齐的增量操作 |

## 2. 使用场景与创作模式

### 2.1 主线流程（七步，原文）

| 步骤 | 名称 | 关键动作 |
| --- | --- | --- |
| 1 | 项目配置 | 确定画面比例、剧本类型、模型策略、创作模式、画面风格 |
| 2 | 剧本创作 | 编写、粘贴或导入本集剧本 |
| 3 | 素材准备 | 从剧本提取资产，并生成或导入参考图 |
| 4 | 分镜设计 | 把故事拆成镜头，编写画面、台词、生成提示词，并生成分镜图 |
| 5 | 视频生成 | 基于分镜图和参考资产生成视频片段 |
| 6 | 音画同步 | 生成角色配音，并把配音与分镜视频做口型同步 |
| 7 | 视频预览 | 视频、配音、字幕、音乐放入时间轴，预览并导出成片 |

> 需求：七步须可作为**线性向导**推进，也允许在已解锁的步骤间**任意跳转与回改**；前置步骤未完成时，后续步骤应给出明确的阻塞提示而非静默失败。〔推断：原文未描述步骤跳转规则，此处按常规创作工具约定〕

### 2.2 创作模式与选型建议（原文）

| 场景 | 推荐模式 |
| --- | --- |
| 单集短片、宣传短片、漫画视频 | 电影 / 短片 |
| 连载漫剧、连续剧 | 电视剧集 |
| 角色对话、剧情推进、镜头表演 | 剧情演绎 |
| 旁白为主、真人解说漫、知识或故事讲解 | 真人解说漫 |
| 已有稳定人物图，希望用图片约束视频 | 图生视频 |
| 需要同时引用场景、角色、道具等多张素材 | 多参生视频 |
| 需要复杂镜头组织和更精细控制 | 专业版 |
| 希望自动生成宫格镜头并形成镜头组 | 自动网格模式 |

> 需求：创作模式须作为**配置项而非代码分支**，每种模式需声明其能力集（是否支持多参、是否自动拆宫格、是否走剧情演绎提示词模板等）。〔推断：模式在原文中表现类似"预设组合"〕

## 3. 功能需求

> 优先级：P0 = MVP 必须；P1 = 商业化上线必须；P2 = 增强。
> 状态标注：**原文** = 来源文章明确描述；**推断** = 为保证可实现性补充的定义。

### 3.1 模块一：项目 / 剧本 / 分集管理（P0）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-1.1 | 作品级项目 | 创建项目，配置画面比例、剧本类型、模型策略、创作模式、画面风格 |
| FR-1.2 | 双结构支持 | 支持「电影（单片）」与「剧集（多分集）」两种内容结构 |
| FR-1.3 | 剧本输入 | 支持在线编写、粘贴、文件导入三种方式 |
| FR-1.4 | 剧本版本 | 剧本需维护版本历史，可回溯与对比〔原文提到 `script/` 负责"剧本版本"〕 |
| FR-1.5 | AI 辅助编剧 | 提供 AI 续写/改写/结构化能力（原文：AI 辅助编剧） |
| FR-1.6 | 场景资产自动提取 | 从剧本自动抽取角色 / 场景 / 道具候选列表 |
| FR-1.7 | 画风快照 | 项目级画风参数快照，后续生成默认继承，保证全项目风格一致 |

**验收口径**：新建剧集项目 → 粘贴剧本 → 一键提取资产 → 提取结果可按类型分组且支持人工增删改。

### 3.2 模块二：资产库（P0）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-2.1 | 三类资产管理 | 角色 / 道具 / 场景，可视化卡片式管理 |
| FR-2.2 | 参考图管理 | 每个资产可挂多张参考图，支持上传、生成、替换 |
| FR-2.3 | 角色音色绑定 | 角色资产绑定音色，供配音环节直接复用 |
| FR-2.4 | 跨分集复用 | 资产在项目内跨分集共享，避免重复设定 |
| FR-2.5 | 角色形态 | 同一角色支持多形态（服装/年龄等）分组管理〔原文"角色形态"〕 |
| FR-2.6 | 参考图别名 | 参考图需支持别名，用于提示词内引用与去重 |
| FR-2.7 | 能力截断 | 当模型支持的参考图数量少于引用数量时，按优先级截断并提示用户 |

### 3.3 模块三：分镜工作台（P0，核心）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-3.1 | 分镜脚本生成 | 由剧本切片生成镜头级分镜脚本（批次规划） |
| FR-3.2 | 分镜字段 | 每镜至少包含：画面描述、台词、镜头语言、视频提示词 |
| FR-3.3 | 分镜图生成 | 按分镜提示词调用图片 Provider 生成分镜图 |
| FR-3.4 | 镜头组拆分 | 支持将宫格图/多镜头图拆分为独立镜头，形成镜头组 |
| FR-3.5 | 视频提示词生成 | 由分镜内容自动生成视频侧的提示词 |
| FR-3.6 | 连续性校验 | 相邻分镜做连续性校验（人物/场景/光位/朝向），不一致时提示 |
| FR-3.7 | 批量槽位 | 批量生成需有并发槽位管理与判活，防止重复占用 |
| FR-3.8 | 分镜复制 | 支持分镜原子复制，产物（图片/视频）与参考素材需正确重映射 |
| FR-3.9 | 富文本编辑 | 分镜文案支持富文本（含加粗、颜色等）〔原文前端使用 `quill`/`wangeditor`〕 |

**验收口径**：20 镜剧本 → 一键生成分镜脚本 → 批量出图 → 拆镜头组 → 单镜重生成不影响其他镜头产物引用。

### 3.4 模块四：图片生成（P0）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-4.1 | 文生图 | 纯提示词生成 |
| FR-4.2 | 图生图 | 基于参考图改写/重绘 |
| FR-4.3 | 多图融合 | 多张参考图融合生成 |
| FR-4.4 | 占位符统一解析 | 提示词中引用图片统一使用 `@图片N[名称]` 语法，由系统解析为实际参考图并按模型能力组织 |
| FR-4.5 | 参数合法性前置校验 | 分辨率 / 比例 / 参考图数量等在提交上游前校验，不合法直接拒绝 |

> **FR-4.4 为关键设计**：占位符是"提示词层"与"模型参数层"的解耦点，必须由服务端统一解析，禁止前端拼接最终模型参数。

## 7. 部署与交付要求

### 7.1 方案 A：生产级一键部署（推荐，Docker）

前置条件：全新 64 位 Linux 服务器；关闭 RocketMQ 且中间件同机时最低 **2 核 / 4GB / 40GB 磁盘**。

```bash
cd /root && if command -v curl >/dev/null 2>&1; then \
  curl -fL --retry 3 --connect-timeout 15 -o /root/aid-install.sh https://gitee.com/gzxx-2025/aid-studio/raw/master/deploy/aid.sh || \
  curl -fL --retry 3 --connect-timeout 15 -o /root/aid-install.sh https://raw.githubusercontent.com/gzxx-2025/aid-studio/master/deploy/aid.sh; \
elif command -v wget >/dev/null 2>&1; then \
  wget -O /root/aid-install.sh https://gitee.com/gzxx-2025/aid-studio/raw/master/deploy/aid.sh || \
  wget -O /root/aid-install.sh https://raw.githubusercontent.com/gzxx-2025/aid-studio/master/deploy/aid.sh; \
else echo 'Please install curl or wget first'; exit 1; fi && \
sudo env AID_REMOTE_BOOTSTRAP=1 AID_RELEASE_CHANNEL=auto bash /root/aid-install.sh install
```

安装后常用命令：

```bash
sudo aid default    # 查看用户端 / 管理端访问地址、初始账号
sudo aid            # 交互式管理菜单
sudo aid status     # 服务与中间件状态
sudo aid logs       # 日志
```

默认入口：

| 入口 | 默认地址 | 说明 |
| --- | --- | --- |
| 用户端 | `http://SERVER_IP/` | 默认 80，可用 `HTTP_PORT` 调整 |
| 管理端 | `http://SERVER_IP:8089/<12位随机访问码>` | 访问码首次部署自动生成 |
| 后端 API | `http://SERVER_IP:8080/` | 通常经 Nginx 反代 |

初始管理员：`admin / admin123` —— **首次登录后必须立即改密码**。

### 7.2 方案 B：本地开发（后端 + 中间件）

前置条件：JDK 17+、Maven 3.6+、Docker。

```bash
# 1. 起中间件（MySQL + Redis，自动导入 sql/ 初始化脚本）
cd deploy/docker
docker compose -f docker-compose.middleware.yml up -d
# 需要 RocketMQ 联调时：
# docker compose -f docker-compose.middleware.yml --profile mq up -d

# 2. 构建并启动后端（默认配置已对齐上面的中间件）
cd ../..
mvn clean package -DskipTests
java -jar aid-admin/target/aid-admin.jar
```

验证：`http://localhost:8080`，接口文档 `http://localhost:8080/swagger-ui.html`。

### 7.3 方案 C：本地单独启动前端

**用户创作端（Next.js）**

```bash
cd frontend/web
cp .env.example .env.local     # 修改 NEXT_PROXY_TARGET=http://127.0.0.1:8080
npm install
npm run dev                    # http://localhost:3000
```

生产静态发布用 `npm run generate`，产物在 `dist/public/`。

**管理后台（Vite）**

```bash
cd frontend/admin
npm install
npm run dev                    # http://localhost:5173
```

开发代理默认 `/dev-api → https://apinotify.aidstudio.com.cn`，本地联调请把 `.env.development` 里的 `VITE_BACKEND_HOST` 改为 `http://127.0.0.1:8080`。

### 7.4 启动后第一件事：配置模型

进入管理后台「AI 模型配置」，填写各厂商（文本 / 图片 / 视频 / 语音）的网关地址与密钥、模型能力参数与计费规则，确认权限与成本后再启用。
